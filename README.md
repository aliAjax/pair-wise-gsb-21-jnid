# hxwl-07 航空维修检查清单

按 ATA 章节推进维修放行前检查

## 技术栈

React + Vite + TypeScript + CSS，数据保存在浏览器本地（localStorage），无需后端。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5107

## 业务流程

1. **录入（维修工程师）**：填写机型、ATA 章节（如 ATA 32）、检查区域、检查项目并签署姓名，提交后记录保存为「待复核」。结论选为「缺陷」时，必须同时填写缺陷描述和处理意见才能提交。
2. **复核（放行人员）**：在记录列表对待复核记录执行：
   - **放行**：记录变为「已放行」并锁定，不可再修改、不可再次复核；
   - **退回**：必须填写退回意见，记录变为「已退回」。
3. **退回重提**：工程师在退回记录上修改（页面顶部表单会显示退回意见），提交后重新进入「待复核」，原退回意见保留在流转记录中。
4. 每条记录附带完整流转记录（提交、放行、退回、重新提交的时间、人员、意见）。

## 数据与统计

- 所有检查记录存于浏览器 localStorage（键：`hxwl-07:inspection-records:v1`），重开页面仍可见；首次打开会播种 3 条覆盖三种状态的演示记录，之后以本地数据为准。
- 工程师/放行人员签署姓名同样本地记忆。
- 看板实时统计：检查项总数、缺陷项、待复核数、放行完成率。
- ATA 章节统计表按章节汇总缺陷项数量、缺陷占比及各状态分布。
